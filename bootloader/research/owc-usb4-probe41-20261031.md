# Probe41: OWC USB4 comparison with the preserved-PHY host path

Hardware result pending. The target is OWC Express 1M2 connected directly
with its USB4 cable at Mac port1. Port0 beside Ethernet remains the debug
connection to the ThinkPad. HDMI remains directly connected to the Mac.

Probe40's explicit TB-only path rejects USB4. It must not simply be reused
or have its reset policy forced on OWC: live custom Linux
`7.2.12-usb4sd4-egpu2` reports OWC data status `0x16c00013`, including native
USB2 connectivity, whereas the TB3 Yottamaster reported `0x06010003` without
native USB2/3. Linux CD321x role selection uses those connection flags and
the data-role bit. Source reference is the separately audited checkout
`517fe27a2ce7fa8d03aa6705a10ff4422197ff5d`, tipd/core.c and tps6598x.h.

Probe41 adds an explicit `usb4host` diagnostic selector. It checks USB4,
connection present, at least one native USB connection flag, host data role,
and absence of a conflicting TB flag before selected-host shutdown and PHY
writes. The second existing status snapshot must match the first. A pure
policy helper is tested across 256 mode/status/orientation combinations
and both recorded OWC/Yottamaster status values.

After this guard it uses the existing hostrun path: the USB2 host-role bits
added in Probe38, DWC3 core initialization without resetting the already
trained PHY from Probe39, late PIPE setup, and retained xHCI rings with the
existing USB-DART checks. No new PHY tuning is guessed. Compared to the
older OWC Probe32 this applies the subsequently added host-start and
preserve-PHY work to USB4; compared to Probe40 both the peripheral protocol
and its necessary native-USB role differ. Therefore it is not a controlled
single-variable proof that any one previous fix solves link training.

The question is whether this corrected USB4 host sequence reaches Connected
and permits remote-router control reads, or reproduces the Phase2 stall.
The NHI transactions and observation are bounded as before. Initial U-Boot
USB probing is inherited, but no new USB enumeration is performed after
starting the diagnostic rings. No external PCIe tunnel or SSD read/write
is requested. The existing internal-NVMe file hashes are compared before
and after; reset is mandatory before returning to an OS. Installed boot
files and GRUB default/next entry are not modified.

The M1 watchdog remains configured for 60 seconds with autostart. This and
the existing planned reset are fallback mechanisms, not a guarantee that
Ubuntu's HDMI will recover or that every hang will reboot. Verify SSH,
boot identity and original boot bundle after the run. The external host
runner's timeout alone does not reset the Mac.

Validation before arming: M1 and sandbox builds, all 67 sandbox tests,
unchanged M1 configuration, exact patch reconstruction and frozen payload
hashes. Original driver authorship remains in the underlying source.
No m1n1 source or installed firmware is modified.
